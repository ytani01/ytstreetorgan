# 画面まわりの決めごと

`webroot/` 配下（テンプレート / CSS / JS）を触るときだけ読み込まれる。
テンプレートと URL の組み立て方、live reload、ロールブックのビューアの作りは
ルートの `CLAUDE.md`（常時読み込み）にある。

## フロントエンド

Pico.css v2.1.1 を `webroot/static/css/pico.min.css` に**同梱**している。
CDN は 1 本も読まない（ローカルで動かす道具なので、ネットに繋がっていなくても
レイアウトが崩れないこと）。jQuery / Bootstrap / Font Awesome への依存も無く、
アイコンはインライン SVG、フォントはシステムフォント。

`webroot/static/css/my.css` の**トークンは `:root:root` で定義している**。
Pico が配色を `:root:not([data-theme=dark])`（詳細度 (0,2,0)）で書いているため、
素の `:root` では後から読み込んでも負ける。実際に負けて Pico 既定の水色のままに
なっていた。同じ理由で、**Pico はボタン要素の中で `--pico-color` を上書きする**
ので、自前のコントロールの色は `--hole` のような独自トークンから直接指定する。

## 確認の出し方

**Yes / No は `confirm()`、三択以上は `<dialog>` + `showModal()`**（Pico が
素で面倒を見る）。`confirm()` は 2 択にしかならないので、選択肢が増えたら
`<dialog>` にする。逆に、ただの確認に `<dialog>` を持ち出さない。

| 場面 | 出し方 |
|---|---|
| 履歴の削除（個別 / 全部） | `confirm()` |
| 機種の削除 | `confirm()` |
| 同名アップロード（置き換えて変換 / 前回のファイルで変換 / キャンセル） | `<dialog>` |

入力を伴うもの（機種の追加）は確認ではないので、選択肢の数によらず
`<dialog>`。

`<dialog>` で確認するときは、**ESC や ✕ で閉じた場合もキャンセルと同じ扱い**に
すること（選んだものを覚えてから閉じ、`close` イベント 1 か所で処理する）。

## ロールブックの見え方（画面だけ）

**生成する SVG は変えない。** 線の色も太さもレーザー加工機の都合で
決まっている。`my.css` でページに埋め込んだものを上書きしているだけで、
ダウンロード（`webroot/svg/` のファイルをそのまま返す）には影響しない。

```css
.svgbox > svg path { stroke-width: 1 !important; }
/* 実線の穴は、くり抜いたように黒く塗る。縁の赤は残す */
.svgbox > svg path[style*="stroke:#FF0000"] { fill: var(--punch) !important; }
/* 音階に無い音は、穴と紛れないよう色を薄くする */
.svgbox > svg path[style*="stroke:#000000"] { stroke: var(--off-scale) !important; }
```

- **なぜ要るか**: SVG は `stroke-width:0.2` に
  `vector-effect:non-scaling-stroke` が付いている。これは**変形を無視して
  指定値をそのまま画面の単位で描く**ので、倍率に関わらず 0.2px にしか
  ならず、アンチエイリアスで薄いピンクに潰れて読めない。
  **背景を暗くしても直らない**（線が薄いのであって、コントラストの
  向きの問題ではない）
- **`!important` が要る理由**: 生成側が `<path style="…">` と
  インラインの style 属性で書いているため
- **線を太らせるのではなく塗る理由**: 塗りはパスの内側なので、
  **穴の見かけの大きさが変わらない**。線を太らせると内外に広がって、
  原寸で見たときに穴が少し大きく見えてしまう
- **縁の赤（カットライン）は残すこと。** 黒く塗るだけだと、音階に無い音
  （`#000000` の破線）と色で区別が付かなくなる。どの音が鳴らないかを
  目視するのは、この道具の主要な用途のひとつ
- 音階に無い音は `--off-scale` で**色を薄くする**（黒のままだと、
   くり抜いた穴と紛らわしいため）。**消してはいけない。**
   演奏者が欠落を目視するためにわざと描いている
- **`stroke:#FF0000` は文字列の一致で選んでいる。** `rollbook.py` の
  `HOLE_COLOR` を変えたらここも直すこと（CSS からは import できない）。
  片方だけ変えると黙ってすり抜けるので、`tests/test_rollbook.py` の
  `test_css_selects_holes_by_the_same_color` がずれを見張っている
- `tests/browser/test_rollbook_page.py` が、画面側（1px・実線は塗りあり・
  破線は塗りなし）と、**保存される SVG が無変更である**ことの両方を見ている

**紙の色も同じで、SVG には入っていない**（背景の矩形すら無い）。
`--paper`（古紙っぽい茶）だけで決まる。**明暗テーマで切り替えないこと。**
破線は `#000000` なので、暗い紙にすると消える。あれは「どの音が
鳴らないか」を目視するためのもの。
