# 画面まわりの決めごと

`webroot/` 配下（テンプレート / CSS / JS）を触るときだけ読み込まれる。
テンプレートと URL の組み立て方、live reload、ロールブックのビューアの作りは
ルートの `CLAUDE.md`（常時読み込み）にある。

## フロントエンド

Pico.css v2.1.1 を `webroot/static/css/pico.min.css` に**同梱**している。
CDN は 1 本も読まない（ローカルで動かす道具なので、ネットに繋がっていなくても
レイアウトが崩れないこと）。jQuery / Bootstrap / Font Awesome への依存も無く、
アイコンはインライン SVG、フォントはシステムフォント。

`webroot/static/css/my.css` の**トークンは `:root:root` で定義している**。
Pico が配色を `:root:not([data-theme=dark])`（詳細度 (0,2,0)）で書いているため、
素の `:root` では後から読み込んでも負ける。実際に負けて Pico 既定の水色のままに
なっていた。同じ理由で、**Pico はボタン要素の中で `--pico-color` を上書きする**
ので、自前のコントロールの色は `--hole` のような独自トークンから直接指定する。

## 確認の出し方

**Yes / No は `confirm()`、三択以上は `<dialog>` + `showModal()`**（Pico が
素で面倒を見る）。`confirm()` は 2 択にしかならないので、選択肢が増えたら
`<dialog>` にする。逆に、ただの確認に `<dialog>` を持ち出さない。

| 場面 | 出し方 |
|---|---|
| 履歴の削除（個別 / 全部） | `confirm()` |
| 機種の削除 | `confirm()` |
| 同名アップロード（置き換えて変換 / 前回のファイルで変換 / キャンセル） | `<dialog>` |

入力を伴うもの（機種の追加）は確認ではないので、選択肢の数によらず
`<dialog>`。

`<dialog>` で確認するときは、**ESC や ✕ で閉じた場合もキャンセルと同じ扱い**に
すること（選んだものを覚えてから閉じ、`close` イベント 1 か所で処理する）。

## MIDI の試聴（TODO-063、TODO-068）

いま表示しているロールブックの音を、その機種で実際に鳴る音だけ、
ブラウザで鳴らして確かめられる。同梱した 3 本（Tone.js / core.js /
html-midi-player.js）とバージョンは `docs/tech-stack.md`。

**試聴の対象は「いま出しているブックの移調量」だけ**（TODO-068）。
行ごとの「試聴」列は無い。移調を選ぶと `#transpose-form` の POST で
ページごと作り直されるので、そのたびにプレーヤーも切り替わる。
**JS は要らない**（`midi_audition.js` は TODO-068 で削除した）。

**落とし穴（忘れると黙って壊れる）**

- **`sound-font` 属性は書かないこと自体が必須。** ライブラリの実装は
  「属性なし＝素の Player」「**属性が空文字（`sound-font=""`）＝
  googleapis から音源を取得**」なので、空で書くと外部通信が発生する
  （実装中に実際に書きかけて気付いた）
- **試聴の URL はテンプレートが `<midi-player>` の `src` に丸ごと書く。**
  JS で組み立てない（prefix と引数の付け方が 2 か所に分かれる）
- **自動再生はしない。** 読み込むところまで。ブラウザが止めることが
  あり、環境によって鳴ったり鳴らなかったりする
- **同梱 3 本の読み込み順は Tone → core → midi-player。** UMD なので
  順序が要る。`type="module"` にしない。`base.html` には入れず、
  結果画面（`svg_data` があるとき）でだけ読む
- **`<midi-player>` の中身は Shadow DOM。** 外から触れるのは `::part()`
  だけ。深追いしない
- **同じ高さの連打が 1 つの長い音に聞こえるのは正しい**
  （`merge_overlapping_notes()` による実機の再現。TODO-038）。
  直そうとしないこと

**やらないと決めたこと**

- **ピアノロールの可視化（`visualizer` 属性）は出さない。** 鳴らない音も
  同じ見た目で描くので、ロールブックの実線（穴）／破線（音階に無い音）の
  描き分けと食い違って読み違いを招く。同梱バイト数は変わらないので、
  後から属性を足すだけで出せる
- **JS 側で音階を判定しない。** `note2scale()` を JS に複製することに
  なる
- **試聴した音の MIDI は持ち帰らせない。** 欲しくなったら
  `AuditionMidi` に `Content-Disposition` を足すのが答えで、
  `DownloadTransposedMidi` の中身を変えるのは答えではない

## 移調の候補の表

**列は「移調」だけ**（TODO-054）。「調」「オクターブ」の列は削除した。
実際に効くのは合計の半音数だけで、3 列に分けると読みにくい。
**作り直すボタンは「移調」の列に付ける**（`button[data-transpose]`。
ブラウザテストがこのセレクタで押している）。

**見出しの `<th>` には、中身と同じ寄せ方の class を付ける**（TODO-055）。
`table.hist thead th` が左寄せなので、付け忘れると中身だけ右に寄って
列がずれて見える。`.num` は数値の列、`.act` は操作の列。
**`.hist__act` を `<th>` に付けないこと**（`font-size: 0` で字が消える）。

移調の選択は**生成後のこの表だけ**（TODO-055）。トップ画面にメニューは
置かない。候補は生成しないと出せないので、選ぶ場所が 2 か所あると迷う。

**用語の説明（「移調」とは？）は出さない**（TODO-077）。TODO-056 では
「この表と同じ場所にだけ置く」と決めたが、`_terms.html` は結局どこからも
include されないまま残っていた。**出さないほうに揃えて、テンプレートごと
削除した。** 表の中の説明（`▼` の意味、候補の読み方）も同じ理由で削除。
足すと決めたときは `storgan.html` の `{% else %}` の直後に書く。

**表は中身の幅で、中央に置く**（`width: auto` + `margin-inline: auto`）。
画面幅いっぱいに伸ばすと列が間延びし、左寄せだと広いパネルの隅に
取り残されて見える。ZIP のリンクも同じく中央（`.field__hint--center`）。

**±0（移調しない）の行の値を下回るセルには `▼` と `.is-worse` を付ける**
（TODO-051）。表には「音符の数か音の長さの**片方だけ**改善する候補」と
「いま適用している移調量の行」が残るので、印が無いと「良くない候補が
出ている」と読める。**行を減らして解決しないこと。** どちらを取るかは
曲によるので、選べるように出している（TODO-039）。

比べる相手（±0 の行の値）は `transpose_view()` が
`zero_note_pct` / `zero_sec_pct` として渡す（TODO-076）。
**印の説明は画面に出さない**ので、`has_worse`（印が 1 つでも出るか）の
計算も削除した（TODO-077）。

## 機種設定の音階マッピング

**音名を選ぶと、表全体が音の高さの昇順（低い音が上）に並べ替わる**
（TODO-069）。`'notes'` の並び順がそのままトラック番号なので、
**穴の列の並びも変わる**。表示だけ並べ替えて保存は入力順、という形には
しない（画面の行番号とトラック番号が食い違うため）。

- **並べ替えの基準は MIDI ノート番号。** 音名の文字列で比べると
  `"A#2"` が `"C10"` より後ろに来る。雛形の `<option>` は 0 番から
  127 番まで順に作ってあるので、`selectedIndex` がそのままノート番号になる
- **行を足したときは並べ替えない。** 既定の `C4` のまま末尾に置き、
  音名を選んだ時点で収まるべき位置へ動く
- **並べ替えたあと、選んだ行にフォーカスを戻す。** DOM を動かすと
  フォーカスが外れ、どこへ動いたのか分からなくなる
- トラック番号の振り直し（`updateTrackNumbers()`）は、`aria-label` の
  番号も直す。行が動くのは削除のときだけではない

## ロールブックの見え方（画面だけ）

**生成する SVG は変えない。** 線の色も太さもレーザー加工機の都合で
決まっている。`my.css` でページに埋め込んだものを上書きしているだけで、
ダウンロード（`webroot/svg/` のファイルをそのまま返す）には影響しない。

```css
.svgbox > svg path { stroke-width: 1 !important; }
/* 実線の穴は、くり抜いたように黒く塗る。縁の赤は残す */
.svgbox > svg path[style*="stroke:#FF0000"] { fill: var(--punch) !important; }
/* 音階に無い音は、穴と紛れないよう色を薄くする */
.svgbox > svg path[style*="stroke:#000000"] { stroke: var(--off-scale) !important; }
```

- **なぜ要るか**: SVG は `stroke-width:0.2` に
  `vector-effect:non-scaling-stroke` が付いている。これは**変形を無視して
  指定値をそのまま画面の単位で描く**ので、倍率に関わらず 0.2px にしか
  ならず、アンチエイリアスで薄いピンクに潰れて読めない。
  **背景を暗くしても直らない**（線が薄いのであって、コントラストの
  向きの問題ではない）
- **`!important` が要る理由**: 生成側が `<path style="…">` と
  インラインの style 属性で書いているため
- **線を太らせるのではなく塗る理由**: 塗りはパスの内側なので、
  **穴の見かけの大きさが変わらない**。線を太らせると内外に広がって、
  原寸で見たときに穴が少し大きく見えてしまう
- **縁の赤（カットライン）は残すこと。** 黒く塗るだけだと、音階に無い音
  （`#000000` の破線）と色で区別が付かなくなる。どの音が鳴らないかを
  目視するのは、この道具の主要な用途のひとつ
- 音階に無い音は `--off-scale` で**色を薄くする**（黒のままだと、
   くり抜いた穴と紛らわしいため）。**消してはいけない。**
   演奏者が欠落を目視するためにわざと描いている
- **`stroke:#FF0000` は文字列の一致で選んでいる。** `rollbook.py` の
  `HOLE_COLOR` を変えたらここも直すこと（CSS からは import できない）。
  片方だけ変えると黙ってすり抜けるので、`tests/test_rollbook.py` の
  `test_css_selects_holes_by_the_same_color` がずれを見張っている
- `tests/browser/test_rollbook_page.py` が、画面側（1px・実線は塗りあり・
  破線は塗りなし）と、**保存される SVG が無変更である**ことの両方を見ている

**紙の色も同じで、SVG には入っていない**（背景の矩形すら無い）。
`--paper`（古紙っぽい茶）だけで決まる。**明暗テーマで切り替えないこと。**
破線は `#000000` なので、暗い紙にすると消える。あれは「どの音が
鳴らないか」を目視するためのもの。
