# TODO-033. ビューアで穴が見にくい

画面で見るときだけ、線を 1px にして実線の穴に薄い塗りを入れた。

**原因は白地ではなく、線が 1px 未満なこと。** 生成する SVG は
`stroke-width:0.2` に `vector-effect:non-scaling-stroke` を付けている。
これは**変形を無視して指定値をそのまま画面の単位で描く**ので、倍率に
関わらず 0.2px になり、アンチエイリアスで薄いピンクに潰れる。
背景を暗くしても改善しない（コントラストの向きの問題ではない）。

**SVG は変えない。** 線の色はレーザー加工機の仕様で決まっていて、
太さも変えたくない。ビューアは SVG をページに埋め込んでいるだけなので、
**CSS で上書きすれば画面だけ変わる**。ダウンロードは `webroot/svg/` の
ファイルをそのまま返すので、渡すファイルは無変更のまま。

決めたこと:

- 線は 1px。`style="…"` 属性で書かれているので `!important` が要る
- **実線（開ける穴）にだけ薄い赤の塗り**を入れる。塗りはパスの内側なので
  **穴の見かけの大きさが変わらない**（線を太くするだけだと、輪郭が内外に
  太って穴が少し大きく見える）
- 破線（音階に無い音）は塗らない。これで**実線＝塗りあり / 破線＝線だけ**と
  意味の違いも一目で分かる
- 低倍率では輪郭だけの矩形は消えるが、塗りは残る

## 入れたもの

`webroot/static/css/my.css` の `.svgbox > svg` の直後に、これだけ足した
（既存の行の変更・削除は無し。コミット `05c097b`）。

```css
.svgbox > svg path {
  stroke-width: 1 !important;
}
.svgbox > svg path[style*="stroke:#FF0000"] {
  fill: rgba(255, 0, 0, .35) !important;
}
```

| 書いたもの | 何をしているか |
|---|---|
| `.svgbox > svg path` | ビューアに埋め込んだ SVG の全パス（穴・破線・外枠） |
| `stroke-width: 1 !important` | `0.2` を上書き。生成側が `<path style="…">` と**インラインの style 属性**で書いているので、`!important` でないと勝てない |
| `path[style*="stroke:#FF0000"]` | style 属性の**文字列に `stroke:#FF0000` を含むパスだけ**＝実線の穴。破線（`#000000`）と外枠（`#0000FF`）には当たらない |
| `fill: rgba(255, 0, 0, .35)` | 生成側の `fill:none` を上書きして内側を塗る |

調整するなら、塗りの濃さは `.35`、線の太さは `1`。どちらも 1 か所。

## 確かめたこと

- CSS を外すと、画面での計算値は **`0.2px`** に戻る（診断どおり）
- ダウンロードされる SVG には `stroke-width:0.2` と `fill:none` が残る。
  ビューアの SVG はページに埋め込んだもの、ダウンロードは
  `webroot/svg/` のファイルを読んで返すので、経路が別
- 原寸・高さ合わせ・全体の 3 つの倍率で見え方を確認した

**色の一致はテストで見張っている。** CSS は `stroke:#FF0000` という
文字列でパスを選んでいて、CSS からは定数を import できない。
`rollbook.HOLE_COLOR` を変えると黙ってすり抜けて塗られなくなるので、
`test_css_selects_holes_by_the_same_color` がずれを検出する
（コミット `548ab81`）。

**ブラウザテストではこの食い違いを捕まえられなかった。** テストサーバーは
起動時に `rollbook` を import 済みなので、ソースの色を変えても生成される
SVG は変わらず、素通りしてしまう。だからファイルを読むだけの静的な
チェックにした。
