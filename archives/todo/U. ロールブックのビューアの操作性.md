# U. ロールブックのビューアの操作性

帯（ミニマップ）のドラッグ（U-2）だけ実施。**ホイールとピンチ（U-1）は
対応しない**ことにした。

いまの操作（`viewer.js`。当時は `storgan.js` の後半）:

| 操作          | 挙動                                |
| ----------- | --------------------------------- |
| ホイール        | **スクロール**（縦横）。拡縮は Ctrl / ⌘ を押しながら |
| トラックパッドのピンチ | 効く（ブラウザが Ctrl + ホイールとして送るため）      |
| スマホのピンチ     | 効かない（touch イベントで、ホイールにはならない）      |
| SVG 上のドラッグ  | パン（`pointerdown` / `pointermove`） |
| 帯（ミニマップ）    | クリックでその位置へ。**ドラッグで送れる**           |

## U-1. ホイールとピンチでの拡大縮小（対応しない）

**素のホイールを拡縮に使うと、いまのスクロールを自分で捨てることになる。**
このビューアは transform を使わず SVG の描画サイズそのものを変えていて、
**ブラウザ標準のスクロールがそのまま効くこと**が設計の要になっている
（CLAUDE.md「ロールブックのビューア」参照）。素のホイールを
`preventDefault()` すると、その利点が失われる。

拡縮の手段は既に足りている（Ctrl / ⌘ + ホイール、トラックパッドのピンチ、
倍率スライダ、高さ合わせ / 全体 / 原寸のボタン）ので、**このままとする**。
スマホのピンチも同じ理由で追わない。

## U-2. 帯（ミニマップ）のドラッグ

`click` をやめ、`pointerdown` → `pointermove` → `pointerup` にした。
`setPointerCapture()` で帯の外へ出ても追従する（SVG 上のパンと同じ作り）。

**掴んだ場所で分けた。**

| 押した場所 | 動き |
|---|---|
| 枠（`.minimap__window` = いま見えている範囲）| 飛ばさない。掴んだ点を保ったまま**相対移動** |
| それ以外 | 押した点が中央に来るよう**その位置へ飛ぶ**（従来のクリックと同じ）。以後は追従 |

枠を掴んだときに飛ばすと、少しだけずらしたいときに中央へ跳ねて扱いにくい。
スクロールバーの摘まみと同じ感覚に合わせた。

指での操作のために `.minimap` に **`touch-action: none`** を付けてある
（既定のままだとページの縦スクロールに取られる）。`pointerdown` の
`preventDefault()` だけでは足りない。

`.minimap__edge`（START / END の字）は `pointer-events: none` なので
そのまま素通りする。

ブラウザテストを 2 本足した。**相対移動の確認は離す前に見ること**
（離してからだと、飛ばすだけの実装でも同じ位置に着いてしまい素通りする）。
