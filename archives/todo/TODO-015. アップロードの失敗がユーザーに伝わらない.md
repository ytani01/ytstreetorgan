# TODO-015. アップロードの失敗がユーザーに伝わらない

旧番号: **J**（コミットメッセージはこの記号で書いてある）

F で見つけた 2 件。どちらも**画面ごと失われて、利用者は選び直すこともできず
ブラウザの戻るしかない**状態だった。

- MIDI でないファイル / 壊れたファイル → 素の 500 ページ
- サイズ上限超え → 真っ白なページ

直し方:

1. `Handler1.post()` の `parse_to_file()` を `try` で囲み、失敗したら
   `_render(msg=..., msg_error=True)` でファイル選択の画面に戻す。
   `msg` は元から `.drop__status` に出る経路があったので、そこに理由を出す。
   `msg_error` は表示を赤くするためだけのフラグ（`.drop__status--error`）
2. 上限超えはハンドラまで来ない（tornado が `max_buffer_size` で本文を
   読まずに接続を切る）ので、**送る前に JS で止める**。テンプレートに
   `size_limit_bytes`（丸めていない素のバイト数）を足し、`storgan.js` が
   `input.files[0].size` と比べる。`<input>` の `onchange` 直書きはやめ、
   送信も JS が受け持つようにした

**併せて、読み込めなかったファイルを残さないようにした。** `post()` は
`if not file1_path.exists()` で書き込みを省くので、壊れたファイルが
`webroot/midi/` に残ると、次に同じ名前で正しいファイルを送っても
壊れたほうが使われる。失敗時に消すようにして、回帰テストも足した
（`unlink` を外すと落ちることを確認済み）。

ブラウザテストは現状固定から**あるべき挙動の確認**に書き換えた（22 本 → 23 本）。
