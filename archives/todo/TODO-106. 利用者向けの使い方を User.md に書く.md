## きっかけ

利用者向けの説明が README の CLI 3 行しか無かった。Web UI は画面が
5 つ（生成・履歴・機種設定と、持ち帰り・試聴）あるのに、どこにも説明が
無く、初めて触る人が移調候補の意味も試聴の位置付けも分からない。

## やったこと

- **`docs/User.md` を新しく作った**（390 行）。できること / 画面で使う言葉 /
  ブラウザで使う / コマンドラインで使う / 困ったとき の 5 章
  - 用語は `CLAUDE.md`「画面に出す用語」の表に合わせた。ブラウザの説明に
    「調」「オクターブ」は出さず、CLI の表を説明する節にだけ出す
  - ビューアの操作、移調の候補の表の読み方、試聴が何の音なのか、履歴の
    2 つの一覧の押したときの違いを、実装と突き合わせて書いた
  - CLI は 4 サブコマンドのオプションを表にし、実際の出力を貼った
- **スクリーンショットを 5 枚入れた**（`docs/images/web-*.png`）。
  利用者から「キャプチャ画像も使って」と指示があった
- **`docs/images/make_shots.py` を足した。** 画像を撮り直すスクリプト。
  `tests/browser/conftest.py` と同じやり方でサーバーを隔離して起動するので、
  利用者の実設定 `~/etc/storgan-conf.json` には触らない。撮る MIDI は
  `tests/data/` のもの（`tests/data/make_midi.py` と同じ理由で、実曲は置かない）
- **README から `docs/User.md` へリンクした。** ついでに 3 つの文書を
  表にまとめた。`docs/Developer.md` には画像の撮り直し方の節を足した

### 決めたこと

- **画像は 2 倍で撮る**（`device_scale_factor=2`）。等倍だと文字が潰れる。
  5 枚で 712 KB
- **画像を全画面で撮らない。** 説明したい範囲を `clip` で切り出す。
  余白ばかりの画像になり、何を見ればよいか分からなくなる
- **生成結果は穴が密なところを見せる。** 曲の先頭は長い音だけで、
  紙の余白ばかりが写る

## テスト

`docs/Developer.md`「一括で回す」の 4 つを verifier が走らせ、すべて
終了コード 0（`pytest -m ""` は 352 件）。

文書の再現は verifier に分けた（TODO-017 の決まり）。確かめたのは:

- `docs/User.md` に貼ったコマンド例が、そのとおりに動くか
- 貼った出力例 3 つ（`rollbook` の候補の表、`parse -v` の図、
  `transpose_summary()` の 1 行）が実際の出力と一致するか
- オプションの表 4 つが `--help` と一致するか
- 画面のラベル・ボタン・列の説明が、テンプレートと JS と一致するか
- `make_shots.py` が動き、利用者の実設定に触らないか

いずれも食い違い無し。
