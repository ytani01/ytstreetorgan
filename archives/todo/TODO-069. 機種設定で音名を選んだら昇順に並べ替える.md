# TODO-069. 機種設定で音名を選んだら昇順に並べ替える

## きっかけ

機種設定の音階マッピングは、音名をドロップダウンで選ぶ形になっている
（TODO-064）。選び直したときに行がその場に留まるので、表の途中に高い音が
混ざったまま気付きにくかった。音名リスト全体を並べ替えたい。

## 決めごと

**音の高さの昇順（低い音が上）に並べ替える。**

`'notes'` の並び順がそのままトラック番号なので、**穴の列の並びも変わる**。
「表示だけ並べ替えて保存は入力順」という形にはしない。画面の行番号と
トラック番号が食い違い、どちらを見ているのか分からなくなるため。

TODO-067 のあとに着手した。`base_note` を廃止すると並べ替えの基準が
音名（＝MIDI ノート番号）だけになるので、先にやると書き直しになる。

## やったこと

`webroot/static/js/config_editor.js` だけで済んだ。

- `sortNoteRows()` を足し、`note-name-select` の `change` で呼ぶ。
  既にある行を `append()` し直すと（複製ではなく）移動になるので、
  並べ替えた順で入れ直してから番号を振り直す
- **並べ替えの基準は MIDI ノート番号。** 音名の文字列で比べると `"A#2"` が
  `"C10"` より後ろに来る。雛形の `<option>` は 0 番から 127 番まで順に
  作ってあるので、`selectedIndex` がそのままノート番号になる
- 並べ替えは安定なので、**同じ音名の行は元の順のまま隣り合う**
- 並べ替えたあと、**選んだ行にフォーカスを戻す**。DOM を動かすと
  フォーカスが外れ、どこへ動いたのか分からなくなる
- `updateTrackNumbers()` が `aria-label` の番号も直すようにした。
  行が動くのは削除のときだけではなくなったため（削除のときも番号が
  ずれたままだったので、あわせて直った）

**行を足したときは並べ替えない。** 既定の `C4` のまま末尾に置き、音名を
選んだ時点で収まるべき位置へ動く。

**読み込んだ時点では並べ替えない。** 既存の設定を、保存もしていないのに
勝手に組み替えて見せないため。

決めごとは `webroot/CLAUDE.md`「機種設定の音階マッピング」に書いた。

## テスト

`tests/browser/test_config_editor.py` に 2 つ足した。

- `test_selecting_note_name_sorts_rows` — 先頭（F2）を A#2 にすると A2 の
  下へ移り、もともとの A#2 はその下に残る（並べ替えが安定であること）。
  トラック番号も振り直される
- `test_sorted_note_names_are_saved` — 並べ替えた順がそのまま保存される

`test_save_persists_edited_value` は、**先頭より低い音**（`E2`）を選ぶよう
直した。高い音のままだと行が動いてしまい、「保存されるか」の話と並べ替えの
話が混ざるため。

結果: `pytest -q` 291 passed、`pytest -m browser -q` 47 passed、
`ruff check src tests` と `mypy src` は問題なし。ブラウザで実際に選び直して、
行が動くこととフォーカスが残ることも確かめた。
