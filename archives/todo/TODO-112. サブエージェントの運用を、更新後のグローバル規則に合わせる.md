## きっかけ

`~/.claude/CLAUDE.md` が 2026-09-06〜07 に更新され、「コードやファイルを
変える項目では、規模によらず確認の担当を別のサブエージェントに分ける」が
入った。このリポジトリの `CLAUDE.md` には「1 か所の修正や、文書だけの
直しでは編成しない」とあり、正面から食い違っていた。

同時に、グローバル側の定義（`~/.claude/agents/`）の `description` には
「管理者から名指しされたときだけ使う。自動で委譲しないこと。」が入って
いたが、このリポジトリの 5 体には無く、意図しない自動委譲が起きうる
状態だった。

## やったこと

- `CLAUDE.md` のサブエージェントの節に、5 体が実装と調査の担当であることと、
  確認は `~/.claude/agents/` の `verifier`、挙動や分岐が変わる項目では
  `reviewer` も分けることを書いた。`tests` はテストを回して結果を報告する
  担当で、確認の担当の代わりにはならないことも添えた
- 「1 か所の修正や、文書だけの直しでは編成しない」を、
  「文書や定義ファイルだけを変える項目で、確かめる中身が『書式が揃って
  いるか』しか無いときは編成しない。それ以外は 1 か所の修正でも確認の
  担当を分ける」に書き換えた
- `.claude/agents/*.md` 5 体の `description` の末尾に
  「管理者から名指しされたときだけ使う。自動で委譲しないこと。」を足した。
  文面はグローバル側の 4 体に揃えた（太字などの装飾は付けない）

### 決めたこと

- **5 体（`core` / `web` / `tests` / `docs` / `survey`）の構成は変えない。**
  グローバルの方針は「工程で切って 3〜4 個に絞る」だが、ドメインで切ったのは
  TODO-088 の判断で実績もある。グローバルの `implementer` / `reviewer` /
  `verifier` / `wording` と併存させ、確認・レビューだけそちらに寄せる
- **グローバル側の他の更新は、このリポジトリでは対応不要。**
  `show-image` skill と Bash の hook（`cp` / `mv` / `rm` の裸実行と
  `git push` を止める）はグローバルで完結する。codegraph は `.codegraph/` が
  無いので使わない。`token-usage.py` の集計手順は、`CLAUDE.md` が既に
  `todo-workflow` skill を指していて追従済みだった

## 確かめたこと

- 5 体の frontmatter が YAML として読めること（`name` / `description` /
  `tools` / `model` / `effort` が取れる。`web` だけ `tools` が無いのは
  TODO-088 のとおり）
- コードは変更していないので `pytest` / `ruff` / `mypy` は回していない

## 残ること

**`.claude/agents/` は Claude Code の起動時にしか読まれない。**
`description` の変更を効かせるには再起動が要る（実行するのは利用者）。
