# TODO-030. 履歴の行の操作を整理する

旧番号: **V**（コミットメッセージはこの記号で書いてある）

行あたり 3 つ並んでいたボタンを、**名前 + アイコン 2 つ**にした。

| 列 | 前 | あと |
|---|---|---|
| ファイル | ただの文字 | **押せる**（MIDI = 再生成 / SVG = 表示） |
| 操作 | `再生成` or `表示` / `保存` / `✕` | 保存（↓）/ 削除（ゴミ箱）のアイコン |

## V-1. ファイル名クリックで 再生成 / 表示

一番自然な操作（そのファイルを使う）を名前そのものに寄せた。
名前は `<button class="hist__open">` で包んである。**`<td>` に `click` を
付けていない**（キーボードで辿れず、フォーカスも当たらないため）。

`data-regen` / `data-show` をその `<button>` へ移しただけなので、
`history.js` の委譲（`e.target.closest("[data-regen]")`）はそのまま。

文字のボタンが無くなって**何が起きるか一見して分からなくなる**ぶんは、

- `title` に元のボタンの説明をそのまま残す
- `aria-label` は「`<名前>` から作り直す」「`<名前>` をそのまま表示」
- 注記を「ファイル名を押すと…」に書き直し、**一覧より前**（タイトルの
  すぐ下）へ移した。触る前に目に入る位置でないと意味が無いため
- 点線の下線を敷き、ホバーで実線にする（押せる場所だと分かるように）

## V-2. 「保存」「削除」をアイコンに

**インライン SVG**。`history.html` の頭で `<symbol>` を 1 度だけ定義し、
行からは `<use href="#i-save">` / `#i-trash` で参照する。アイコンフォントも
CDN も使わない（CLAUDE.md「フロントエンド」）。色は `.icon` の
`stroke: currentColor` が継承で決まるので、削除だけ赤くなる。

- **字が無くなるので `title` と `aria-label` は必須。** ブラウザテストが
  両方のアイコンに `aria-label` があることを見ている
- 押せる範囲は `.btn-row.btn-icon` の `min-width` / `min-height` で確保
- `.icon { pointer-events: none }`。`e.target` が `<svg>` になっても
  `closest()` は効くが、狙いをボタンに固定しておく
- 設定エディタの行削除（`.btn-delete-row` の `✕`）は**そのまま**。
  あちらはファイルではなくフォームの行を消すもので、別物
- 削除の確認は `confirm()` のまま（P の方針どおり。2 択なので）

## V-3. 列を詰めてファイル名の幅を稼ぐ

名前は長いほうが分かるので、他の列を削って回した。1200px 幅・パネル半分
（562px）での実測で **236px → 281px**（+19%）。

- 列の間の padding を `.5rem` → `.3rem`。**表の左右端だけ `.7rem` 残す**
  （端まで詰めると窮屈に見えるため）
- サイズと更新は等幅なので `font-size: .74rem` に落とす
- アイコンのボタンは `min-width` を `1.8rem` → `1.45rem`（実測 42px →
  35px。押せる範囲としてはまだ十分）。`.hist__act { font-size: 0 }` で
  インライン要素の間の空白も消す
- 詰めたら見出しが「サイ / ズ」と折れたので `thead th { white-space: nowrap }`
- 名前は溢れると `…` で切れるので、`title` の頭に名前を入れてある
