# TODO-103. アップロード画面の説明を、タイトルの下にまとめる

## きっかけ

アップロード画面の説明が 4 か所に散っていて、読む順番が分かりにくかった。

| 今の場所 | 中身 | 扱い |
|---|---|---|
| `storgan.html:26` リード | MIDI からロールブックを作る | そのまま |
| `storgan.html:50-53` 機種セレクトの下 | 音階に無い音の扱い、生成後に候補が出る | **移す** |
| `storgan.html:66-69` ドロップ欄 | `.mid` / `.midi`、サイズの上限 | そのまま |
| `storgan.html:82-85` フォームの下 | サーバーに残る、履歴から削除（TODO-102） | **移す** |

移す 2 つは、どちらも個々の操作の説明ではなく画面全体の振る舞いの話。
今の位置だと、すぐ上の操作（機種を選ぶ・ファイルを選ぶ）の説明に見えて
誤解を招く。特に保存と削除の案内は、フォームの下にあるせいで
「アップロードした後の話」に読める。

ドロップ欄の `.mid` / サイズの上限は動かさなかった。あれは入力欄そのものの
仕様で、ファイルを選ぶ瞬間に目に入る位置にあることに意味がある。

## やったこと

`webroot/templates/storgan.html` の機種セレクトの下とフォームの下にあった
説明を、リード（`page-lead`）の下へまとめて移した。

段落 1 つに文章をまとめると 1 文が長くなって読みにくかったので、箇条書き
（`<ul class="field__hint field__hint--list">`）にした。

```html
<ul class="field__hint field__hint--list">
  <li>機種の音階に無い音は穴が開きませんが、キーを変えて音源に近いメロディーになるよう最適化します。</li>
  <li>生成後、候補の一覧を表示します。</li>
  <li>アップロードした MIDI と生成した SVG はサーバーに残ります。<a href="{{urlprefix}}/history">履歴</a>から削除できます。</li>
</ul>
```

`webroot/static/css/my.css` に `.field__hint--list` を足し、`<ul>` の余白と
行間を詰めた（既存の `.field__hint` の字の小ささはそのまま引き継ぐ）。

箇条書きにしたことでドロップ欄が下へ押し出されるが、それは構わないと
利用者が判断した（当初の懸念だった「3〜4 行に収める」「押し出されないか
確かめる」は取り下げた）。

Playwright でスクリーンショットを撮り、3 項目の箇条書きとして表示され、
ドロップ欄が押し出されても崩れていないことを確認した。

## テスト

文言を見る既存のテストは無く、追従も不要だった。

`pytest` / `ruff` / `mypy` はすべて通った。
