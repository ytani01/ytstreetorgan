# TODO-012. 生成した SVG をブラウザ上でズーム・スクロールできるように

旧番号: **H**（コミットメッセージはこの記号で書いてある）

`.svgbox` を倍率つきのビューアにした。ツールバー（倍率スライダ / ± /
高さ合わせ / 全体 / 原寸 / 先頭へ）、位置と演奏時間の読み取り、ミニマップの帯、
Ctrl + ホイールでの拡縮、ドラッグでのパンまで。実装は `storgan.js` の後半。

**transform では拡縮していない。SVG の描画サイズそのものを変えている。**
こうするとブラウザ標準のスクロールがそのまま効き、スクロールバーが全体の中の
現在位置を示す。SVG が mm 単位なので倍率 1.0 がそのまま原寸（96dpi 換算）。
汎用の panzoom ライブラリは transform ベースで、縦横比 33:1 のロールブックでは
スクロールバーが消えて現在位置を見失うので使わなかった。

- 既定は「高さ合わせ」（`d-kaeru.mid` / 34notes で 75%）。「全体」は 7% に
  なって何も読めないので既定にしない
- **初期表示は右端。** `viewBox` が負で、曲の先頭が x=0 側 = 右端にあるため
- `1sec` = 50mm なので、スクロール位置がそのまま演奏時間になる

`RollBook` に `width` / `height` / `hole_count` / `mm_per_sec` を足した。
`Handler1._render()` が `book` として別に渡し、テンプレートが
`window.BOOK_DATA` に出している。

（**追記**: このとき「寸法は SVG からは取り出せない」と書いたが、
`width` / `height` は `<svg width="…mm" height="…mm">` に出ている。
取り出せないのは穴の数と `mm_per_sec` のほう。）

`Handler1` は `post()` が `get(svg_data=...)` を呼ぶ形をやめて、描画を
`_render()` に分けた。GET ハンドラを描画関数として使い回すのは分かりにくく、
`svg_data` が「画面の切り替えフラグ」を兼ねているのも読みにくかった。

ビューアのブラウザテストを 2 本追加（初期位置が右端であること、倍率ボタン）。
倍率の絶対値ではなく「横スクロールが消えるか」で判定しているので、
ウィンドウ幅に依存しない。
