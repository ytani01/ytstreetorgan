## きっかけ

`~/.claude/CLAUDE.md`（全プロジェクト共通）が 2026-09-05 に更新され、
`archives/todo/` に書く表が 2 つに分かれた。担当ごとにモデル・effort・
`output`・`cache_creation`・料金の割合を書く形で、**集計の方法は
プロジェクト側の `CLAUDE.md` に書く**という決まりも付いた。このリポジトリには
その記述が無い。

突き合わせたところ、他にも 2 点ずれていた。

- **SessionStart フックが二重だった。** グローバルの
  `~/.claude/hooks/todo-count.sh` が全プロジェクトで走るのに、
  `.claude/settings.json` にも同じものがあった。しかも `/^### /` で
  数えていて、項目の見出しは `## TODO-NNN.`（h2）なので**常に 0 件**。
  TODO-082 で直したのはチェックボックスを数えていた点で、見出しの
  レベルは合っていなかった
- **`TODO.md` の骨格**が `# = TODO` / `## == 完了済み` /
  `## == 着手前 / 検討中` で、グローバルの形と違った。グローバルの
  フックは `## 完了済み` / `## TODO-NNN.` を前提にするので、揃えないと
  フックを任せられない

## やったこと

1. **`TODO.md` の骨格をグローバルの形に揃えた。** `# TODO` /
   `## 完了済み`、`=` 記法と `## == 着手前 / 検討中` を外し、冒頭を
   「**残っている項目: TODO-088。** これまでに 87 件を決着させた」に
   書き換えた。
2. **`.claude/settings.json` を削除した。** 中身は SessionStart フック
   だけで、グローバルと二重だった。
3. **`CLAUDE.md` に「トークン消費量の集計」の節を足した**（§ *コマンド*
   の末尾）。集計は `~/bin/token-usage.py`（実体は
   `~/dot.files/token-usage.py`。`~/dot.emacs.d` の TODO-021 で
   ytsched 版から汎用化されたもの）をそのまま使う。**移植は要らなかった。**
   標準ライブラリだけで動き、cwd から
   `~/.claude/projects/-home-ytani-work-ytstreetorgan/` を割り出す。

## やらなかったこと

- **過去 87 件のアーカイブに表を足すことはしない**（TODO-057 で
  「過去は直さない」と決めてある）。そもそも**TODO-087 以前は数字が
  出ない** — transcript が 2026-09-05 以降しか残っていない
- **`.claude/agents/` は置かない。** `~/.claude/agents/` の汎用版
  4 つ（implementer / reviewer / verifier / wording）で足りている。
  `~/dot.emacs.d` は 3 つを同名で全文上書きしているが、差分は
  `check_init.sh` のような**そのリポジトリ固有の事情**だけで、
  frontmatter は汎用版と完全に一致していた
- **`archives/agents/TODO-063` と `TODO-067` に残っている当時の定義
  ファイル本体は消さない。** グローバルは「定義は archives へ移さない」
  だが、これも過去の名残なので触らない

## テスト

`verifier` に確認させた（報告は `archives/agents/TODO-088/verifier-report.md`）。

- グローバルのフックを手で流し、`{"systemMessage": "TODOに残っているのは、1 件"}`
  を得た。旧フック（`/^### /`）では 0 件だったことも確かめた
- `CLAUDE.md` に書いた 3 つのコマンド例を実際に走らせ、パス・`PRICING` の
  実在・割り出し先・出力末尾の文言まで実物と一致することを確かめた。
  `token-usage.py TODO-087` は書いたとおり `この範囲の transcript が

  合っていることを数えた

## 分担の振り返り

- **verifier の発見はゼロ**だった。ただし、main が省きがちな 2 つ
  ——「書いた 3 つのコマンド例を実際に走らせる」「消したファイルへの参照を
  リポジトリ全体から探す」——を実際にやっている。報告のおかげで
  `CLAUDE.md` の出力末尾の文言を実物どおり（`（参考: cache_read …、
  メッセージ …）`）に直せた
- **見込みと食い違わなかった。** 立てた時点で範囲（3 ファイル）が
  見えていたので、見込みも実施も `Opus 5 / effort medium` + `verifier`
  のままで済んだ
- **次に同じ規模——文書と設定ファイルだけ、ただし書いたとおりに試せる
  コマンド例を含む——の項目をやるときも `verifier` を 1 人だけ立てる。**
  料金の割合は 8% で、これは安い。ただし今回は依頼に 5 項目を並べた結果
  20 メッセージ使っている。**依頼は「新しく書いたコマンド例を実際に
  走らせる」と「消したものへの参照を探す」の 2 つに絞る。** 骨格が
  グローバルの形と合っているかの照合は、main が diff を見れば済む
